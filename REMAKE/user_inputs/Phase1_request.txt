# 6. 第四阶段：识别真正有价值的文件

不要简单使用“最后修改时间”判断价值。

对重要文件进行分类：

## CANONICAL

当前 restart 项目真正应该保留的核心文件。

例如：

- 核心模型函数
- 最终参数拟合函数
- 必需的数据
- 最终绘图脚本
- 报告中实际使用的模型

## LEGACY-BUT-INFORMATIVE

不属于最终 pipeline，但有助于理解研究演化。

例如：

- 旧模型
- 失败的参数识别方案
- 旧实验
- 对比算法

这些一般不要放进主 src，但可以保存在：

`legacy/`

或只在文档中映射到原项目。

## REDUNDANT / GENERATED

例如：

- duplicate
- copy
- backup
- cache
- generated intermediate result
- identical figure
- temporary output

这些通常不需要进入 restart。

## UNKNOWN

无法确认意义的文件。

不要擅自丢弃。
